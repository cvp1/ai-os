Upgrade · optional · reversible

Give your AI-OS a memory with history

The memory mesh replaces "a file your agent edits" with an append-only event log: every belief has a history, contradictions get detected instead of silently coexisting, and you can replay exactly what your agent believed at any past moment. It runs complete on one machine; more machines can enroll later and share one set of beliefs.

The full design — including its honest gaps — is written up in the memory-mesh spec. This page is just the upgrade path.

Is this for you?

Your AI-OS keeps working exactly as it is without this. Upgrade if any of these ring true: you run sessions in parallel and have caught your memory index losing lines; you want to know when and why a remembered fact changed, not just its latest wording; or you run (or plan to run) your assistant on more than one machine and want them to disagree loudly instead of silently.

What the upgrade actually does

  • Adds a memory-mesh/ component beside your existing workspace content. Your notes, your CLAUDE.md, and your memory files are not touched.
  • Backfills your current always-on memory notes as the first events, and preserves your on-demand catalog.
  • Flips your MEMORY.md index to generated — rebuilt from the event log every few minutes. Your hand-built index is kept at MEMORY.md.pre-mesh.
  • Schedules a small fold job (plain Python, no AI in it) that rebuilds the index and parks contradictions.

Reverting is one step: delete the .mesh-generated marker in your memory store and restore MEMORY.md.pre-mesh. The event log just stops being consumed.

The upgrade

From a terminal (or paste these to your agent and have it run them, one at a time):

git clone https://github.com/cvp1/ai-os-seed
python3 ai-os-seed/install.py --target <your-workspace> --into
bash <your-workspace>/memory-mesh/install.sh

Then verify two things: your MEMORY.md now opens with a GENERATED by memory-mesh fold header, and it still carries the same notes it did before. If either is off, revert (above) and nothing is lost.

--into refuses to overwrite anything that already exists — if your workspace already has a directory named the same as a seed component (say, skills/), it stops before moving a single byte and tells you. That upgrade becomes a by-hand merge; ask your agent to reconcile the two directories first.

One habit changes

After the flip, MEMORY.md is a view, not a file to edit — hand edits get rebuilt away within minutes. New durable lessons enter through an event instead (/improve does this for you):

python3 <your-workspace>/memory-mesh/emit.py --kind lesson \
  --subject lesson/<short-slug> --content "the one-line rule" --session <label>

Re-emitting the same subject supersedes the old wording — that's the update path. Memory files work exactly as before; only the index maintenance moved.

More machines, later

Solo is the default and is fully functional. When you add a second machine, the mesh becomes peer-to-peer: each machine carries every machine's events over plain git-over-ssh (no server), and a contradiction between machines parks on all of them within minutes. The enrollment runbook ships with the component: memory-mesh/ENROLL.md — including optional signed truth, where only a key you hold can settle a disagreement.
